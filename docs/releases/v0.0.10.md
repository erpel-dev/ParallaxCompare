ParallaxCompare 0.0.10 adds S-CORE configuration comparisons, schema-assisted FlatBuffers decoding and structured requirements/interface views. It also includes the latest security hardening for paths, archives and remote repositories.

## New

- **S-CORE JSON configurations:** recognised communication, lifecycle, logging, parameter and FEO configurations use a stable representation. Known named collections align by identity; process arguments, dependencies, parameter matrices and unknown arrays preserve their order. Decimal values retain their precision.
- **FlatBuffers data:** decode `.bin`, `.fb`, `.flatbuffer` and `.flatbuffers` with a matching schema. Same-name `.bfbs` or `.fbs` sidecars are discovered per side, including in archives and Git revisions. The desktop **Schemas** menu selects a shared schema or separate schemas; the CLI offers `--schema`, `--left-schema` and `--right-schema`. Equivalent values compare equally despite different binary packing, and schema changes remain visible.
- **Definitions views:** `.fbs`, `.proto`, `.fidl`, `.fdepl`, `.trlc` and `.rsl` show readable declarations. TRLC requirements and attributes align by identity; field, enum, parameter and deployment order remains visible. FlatBuffers documentation annotations are retained. Additional syntax highlighting covers configuration definitions.

## Security and reliability

- Reject paths that escape compared trees and prevent copying or deleting the compared root itself.
- Bound archive-entry sizes, 7z blocks and compressed-tar expansion. Deeply nested archive paths no longer recurse once per component.
- Reject insecure HTTP/Git remotes by default. `PARALLAX_ALLOW_INSECURE_REMOTES=1` explicitly opts into them.
- Stop waiting indefinitely when a helper process leaves an output pipe open, and validate pull-request URLs consistently in the frontend and backend.
- **LibreOffice conversion has been removed.** Supported legacy Word, Excel, PowerPoint and Visio files continue to use native readers. Older or unsupported files fall back to a raw view.

## FlatBuffers requirements and limits

`.bfbs` reflection schemas are decoded directly, without an external tool. Compiling a text `.fbs` schema for binary decoding requires **`flatc` on PATH** (tested with 24.3.25). Viewing an `.fbs` definition needs no compiler. Binary decoding requires a schema with `root_type`; `.bfbs` takes precedence when both same-name sidecars exist.

Malformed data, missing includes, identifier mismatches and populated fields absent from the schema produce errors; the desktop retains a raw fallback. Advanced 64-bit offsets/vectors and schemas with string/vector defaults are currently rejected. Structured views are read-only and do not replace the source formats' validators.

## Validation

335 workspace tests passed on the integrated changes, along with formatting, strict Clippy, frontend checks and native/frontend builds. Desktop checks covered structured views, schema discovery, native schema selection and raw fallbacks. Real S-CORE communication and launch-manager configurations were checked with both text and binary reflection schemas. CI passed on Linux and Windows before release preparation.
