## Automatic source detection

- Replaces the Folder / File or Archive / Git ref / Worktree tabs with two source cards. Paste a path or repository link, or use Browse to choose a folder or a file/archive. Detected-type badges confirm the result.
- Local folders, files, archives, paths inside archives and local Git revision syntax are recognized. Existing paths containing `@` or `!` keep their filesystem meaning.
- Repository folders start with files on disk, including local changes. Choose revision selects a branch, tag or commit, retaining the current file/subfolder scope. Use files on disk switches back. A bare revision asks for its repository.
- Two Git revision sources offer a common-ancestor (merge-base) option. Archive expansion and .gitignore settings are under Comparison options.
- Missing sources, permission errors and invalid local revisions stay visible. Known file/container mismatches disable Compare with an explanation. Detection is debounced, limits concurrent filesystem inspections per card, and discards stale results after editing or swapping.
- Detection does not fetch remote links or enumerate remote refs while typing a source. Remote access is checked on Compare, or when explicitly opening the revision chooser. Archive contents are checked when comparing.

## Pull request preview

- A PR URL pasted into either source supplies the complete pair. Resolve PR explicitly checks access and previews the merge-base and head commits; Compare PR opens that read-only snapshot.
- GitHub Enterprise hosts continue to use the pasted hostname and existing gh/git authentication. Access errors retain the URL and offer Retry. Back to two sources restores the previous pair.
- Changing the URL invalidates its resolved preview. Recent PR comparisons still reopen their saved exact commits; editing a recent PR resolves it again.

## Compatibility and validation

- The Change side popover uses the same simplified picker. Existing saved Git revisions, scopes and explicit worktree sources migrate without losing their meaning.
- README instructions and the New comparison screenshot reflect the new workflow.
- 341 Rust workspace tests and 12 frontend tests passed, together with strict Clippy, formatting, Svelte checks and production frontend/native builds.
- 45 desktop checks cover real comparisons, Git selection and scope, source and access errors, stale detection responses, PR preview/retry, saved-source migration, keyboard focus and the minimum window size. PR success/retry UI checks use controlled responses with real read-only Git comparisons; an unavailable PR also exercises the live gh/git error path.
