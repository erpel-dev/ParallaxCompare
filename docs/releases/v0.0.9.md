ParallaxCompare 0.0.9 adds DCM calibration comparisons, ODX diagnostic descriptions and PDX packages, and read-only GitHub pull request comparisons from the existing GUI path fields.

## New

- **DCM calibration exports (`.dcm`)**: compare scalars, text values, arrays, curves, maps and axes by calibration name, including units and metadata. Decimal normalization preserves precision. Formatting, comments and object order can be marked similar. The calibration header distinguishes DCM exports from DICOM images; unknown statements remain visible.
- **ODX descriptions (`.odx` and `.odx-*`)**: an ODX diagnostics view includes layers, services, requests and responses, parameters, data types, references and vendor extensions. Attributes and named definition collections use a stable order while parameter and other sequence orders remain intact.
- **PDX diagnostic packages (`.pdx`)**: browse and compare packages as ZIP archives, with structured ODX views for embedded descriptions and comparison of auxiliary and flash files. Direct entry paths such as `engine.pdx!/diagnostics/engine.odx-d` work too.
- **Read-only GitHub PR comparisons**: paste a PR URL into either path in New comparison, leave the other path empty, and press Compare. Pasting into an existing comparison's path bar also opens the whole PR. The left side is the merge base and the right side the PR head, with clear labels and immutable commit IDs. GitHub Enterprise hosts and the host's HTTPS/SSH preference are supported. Tool and repository-access failures show errors with authentication guidance and preserve the current comparison.

## Using pull requests

Install `gh` and `git` on the application's PATH and authenticate with `gh auth login --hostname HOST`. Git fetches need working SSH access or an HTTPS credential helper, such as `gh auth setup-git --hostname HOST`. The app reads existing configuration and does not check out a branch or modify the pull request.

Recent comparisons and Refresh retain the opened snapshot. Paste the PR URL again, or edit its recent comparison entry, to resolve the current head and merge base.

## Validation and limits

- 310 workspace tests passed, along with strict Clippy, formatting, frontend checks and native/frontend builds. Desktop checks covered the new file views and ten PR cases, including a live GitHub fork PR, Enterprise HTTPS/SSH fixtures, read-only sources and access failures.
- ODX is a structural comparison: references remain visible by ID, without resolving inheritance or decoding diagnostic traffic. PDX opens as an archive tree.
- Structured calibration and diagnostic views are read-only. Raw text remains available, and malformed inputs fall back to text with a note.
- Git LFS files remain Git pointer files and submodules remain commit references; their external contents are not downloaded.
