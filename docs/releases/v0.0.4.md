ParallaxCompare 0.0.4: editing lines and saving one side, a flat folder view, a command palette and navigation history, new views for source code, AUTOSAR ECUC values and more, a faster text view, much faster archive compares, and fixes for 20 issues from a code review, among them several that could lose data. ParallaxCompare is now MIT licensed.

## Downloads

All files are standalone: no installer, nothing to set up.

| File | What it is |
|---|---|
| `ParallaxCompare-v0.0.4-windows-x64.exe` | Desktop app for Windows 10/11 (x64). Needs the Microsoft Edge WebView2 runtime, which Windows 11 and current Windows 10 already include. |
| `parallax-v0.0.4-windows-x64.exe` | Command-line tool for Windows |
| `ParallaxCompare-v0.0.4-linux-x86_64.AppImage` | Desktop app for Linux (x86-64). `chmod +x` and run. Without FUSE, run it with `--appimage-extract-and-run`. |
| `parallax-v0.0.4-linux-x86_64` | Command-line tool for Linux, statically linked |
| `SHA256SUMS.txt` | Checksums of all files |

The executables are not code-signed yet. Windows SmartScreen will warn on first start ("More info" → "Run anyway").

## New

- **Editing lines** (#6): select lines with Shift+click or Shift+↑/↓ (Ctrl+A for all), then copy, cut, delete or paste them; undo and redo cover these too. A side with changes can be saved on its own from its path bar.
- **Line endings**: when the two files differ only in line endings, one click converts either side to the other's.
- **Flat folder view** (#5): all files in one list, as if they were in one folder. Files with the same name in different folders are matched, compared and marked as moved; open, copy and delete work on the pair.
- **Change a side in place**: click a path bar to type another path (also `repo@v1.4`), use its folder button or side picker, or drop a file or folder on that half of the window.
- **Navigation**: back/forward per tab (also with the mouse's side buttons), Up to the parent folders or back to the folder row, path suggestions with Tab completion (also branch and tag names), Git history of a file from its path bar, "Compare these" for two selected rows, Ctrl+1…9 for tabs.
- **Command palette** (Ctrl+Shift+P, Ctrl+K or F1) with every action and its shortcut; an Options panel for less used settings; a right-click menu on folder rows that names what each copy and delete applies to (#2); recent comparisons with pinning.
- **New content views**, each with a "≈ similar" rule:
  - Source code outlines for Rust, JavaScript/TypeScript, Python and Perl; files that differ only in what rustfmt, Prettier or Black change, or in comments, are similar
  - AUTOSAR EcucValues ARXML as simplified JSON, **editable**: copy differences or edit values, and the ARXML is patched in place
  - Xpand, Xtend and Check (openArchitectureWare), FreeMarker templates, reStructuredText and Sphinx-Needs, Conan lockfiles, graphs, profiles and `conanfile.txt`
- **≈ similar files open in the view where they are equal**, with a note saying why; "Text" still shows every byte difference.
- **Images**: side by side, differing areas are outlined instead of covering the pictures (#7); small images are enlarged to fit; zoom with −/+ or Ctrl+wheel, both sides scrolling together.
- **Option "Verify archive entries byte for byte"** (`--verify-archives` in the CLI): zip and 7z entries with the same CRC32 and size are normally taken as equal without decompressing them; with this option they are compared byte for byte.
- **The new-comparison form accepts every source syntax** (`repo@v1.4`, `repo@HEAD:src`, `archive.zip!/dir`), and `~` stands for the home folder everywhere.

## Faster

- Rows after a copy, undo or redo appear in about 2 ms instead of 110–170 ms, without flicker (#3, #4); scrolling highlights rows about 3.5 times faster.
- Files with hundreds of thousands of differences open in seconds instead of freezing the window.
- Files beyond about 880 000 lines no longer show blank rows at the end.
- **Archives open without being read**: large archives are memory-mapped (on Linux and macOS; Windows still copies them into memory), and only their index is read. Differing zip entries are decompressed only up to their first difference. Two zips with 200 MB of content each: identical ones compare in 1 ms instead of 360 ms, with 20 MB of memory instead of 600 MB; files changed near their start in 8 ms instead of 320 ms.
- A zip with 40 000 files in one folder is indexed in about 1 s instead of 20 s.
- The flat view matches files of a common name (`index.ts` in many folders) without scoring every pair: 1 000 per side take 40 ms instead of 770 ms.
- Summary views of large files (models, media) no longer read all of both files to say whether they are identical.

## Fixed

- Copying a file or folder that exists on one side only did nothing.
- With many tabs, the scrollbar covered the tab titles.
- Typing into a filled path, revision or sub-folder field mixed the new text into the old one.
- Changes inside very long lines (minified files) were not marked; they are now marked and scrolled into view.
- The difference counter did not follow scrolling, and F7/F8 stopped working after scrolling with the mouse.
- From the code review in #8:
  - **Copying a file onto itself** (the same folder on both sides, or a hard link) emptied it; it is now skipped.
  - **Copying over a symlink** wrote through it to the file it points to; the link is now replaced.
  - **Two saves at once** could break each other; each now writes a temporary file of its own.
  - **XLSX numbers** without a cell type were shown as FALSE, so changed numbers counted as similar.
  - Copies keep the executable bit; symlinks written into 7z archives stay symlinks.
  - A symlink and a file with its target as content are no longer reported as the same.
  - Named pipes, sockets and devices no longer make a compare hang.
  - The CLI exits with 2 when entries could not be compared.
  - Closing a comparison no longer leaks its file watcher (after many comparisons, changes on disk were no longer noticed), and a change made by another program right after a save is no longer missed.
  - Expand loads identical Git folders that were skipped; Ctrl+S works from the find field; find highlights matches in long lines; a view that fails on the right side falls back to Text like one that fails on the left.
- Content views no longer crash on source that is not valid in its language (unbalanced brackets in Rust, an unclosed `{` in JSX, indentation at the end of a Python file).

## Known limits

- Fonts and Android DEX files have no content view yet.
- Parquet/Arrow show the file summary, not the data rows.
- Find stops after 20,000 matches; the count then shows a "+".
