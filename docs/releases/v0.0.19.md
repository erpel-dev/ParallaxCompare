ParallaxCompare 0.0.19 makes large comparisons use far less memory, and fixes data-safety and false-equality problems found in exploratory testing.

## Downloads

| File | What it is |
|---|---|
| `ParallaxCompare-v0.0.19-windows-x64.exe` | Portable desktop app for Windows 10/11 (x64). Requires the Microsoft Edge WebView2 runtime. |
| `parallax-v0.0.19-windows-x64.exe` | Command-line tool for Windows |
| `ParallaxCompare-v0.0.19-linux-x86_64.AppImage` | Desktop app for Linux (x86-64). `chmod +x` and run; without FUSE, use `--appimage-extract-and-run`. |

| `LICENSE`, `THIRD-PARTY-NOTICES.md` | License and notices for included code |

This is a prerelease, following the project's convention for 0.x versions. The executables are not code-signed.

## Large comparisons

Measured on a tree of one million files per side, where 10 % of the folders contain a difference:

| | 0.0.18 | 0.0.19 |
|---|---|---|
| Command line, peak memory | 185 MB | 83 MB |
| App, web view process, peak | about 1.9 GiB | about 0.5 GiB |
| App, script and layout time until the result shows | 17.5 s | 1.8 s |

The app now keeps the result and sends the window only what differs. An identical folder is one row with its file count, and its entries load when you open it. Flat view and *Expand all* still load everything, and a folder that contains any difference is still sent whole, so the gain depends on how much is identical. Ranges come from a few single runs.

## Safer comparisons

- **Comparing never changes anything.** A cleanup of leftover `.parallax-tmp` files added in 0.0.18 could delete a file by that name during a comparison. It is gone; those files are listed like any other.
- **A file that changes while it is compared no longer crashes the program.** Files of 128 KiB and more are read as streams instead of memory maps.
- **Names that are not valid UTF-8** make their folder an error instead of being shown with a lossy name that could hide a change.
- **Symlink targets** compare byte for byte; line-ending and encoding rules apply to files only.
- **Zip entries that share a name** are an error, with or without `--verify-archives`.
- **Equality taken from a stored CRC32** says so in the result instead of "same bytes".
- **Large archives:** members of uncompressed tars are streamed, so the 2 GiB limit no longer applies to them. Errors name the member and the limit.
- **Cancel** now works between chunks while a large file is compared.

## Also

- UTF-8 and UTF-16 files with the same text are *similar*, as the text view shows them.
- Control characters in names show as symbols (␊, ␉); the selection bar counts the rows that are shown; the copy arrows no longer cover line numbers; the PR bar and panel count open threads the same way; a small ring marks image differences too small to see.
- Error messages read as sentences, with no internal prefixes.
- Conan profiles that differ only in spacing are *similar* also with `--strict-eol`.
- New tests: contract test between the UI and the app's commands, and smoke tests of the folder view in a browser engine (run in CI on Linux).

## Known limits

- Compressed 7z and zip members are still decompressed into memory, up to 2 GiB.
- The text and hex views still map large files into memory, so a file truncated by another program can crash the app there.
