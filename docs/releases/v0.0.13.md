ParallaxCompare 0.0.13 adds a 3-way merge: a merge view that works as a `git mergetool`, a list of a repository's conflicts, `parallax merge` on the command line, and merging by syntax where lines conflict.

## Merge view

- Local, base and remote are shown above the result, which scrolls along with them. Lines are tinted by where they come from, and changed characters are marked against the base.
- Changes made on one side only are merged by the rules `git merge` uses, so the result starts as Git's file. Conflict markers use the branch names, and `merge.conflictStyle` (`diff3`, `zdiff3`) is respected.
- Each conflict has a bar with Take local, Take remote, Take both (either order) and Keep base, also as Alt+arrow shortcuts. Click any result line to edit it. Undo, redo and Undo choice work for every change.
- Save asks before keeping conflict markers, and asks before replacing a result file that changed on disk since the merge opened.
- Each column scrolls sideways on its own for long lines. An empty result can be typed into.

## Git mergetool and repository conflicts

- `git config mergetool.parallax.cmd 'parallax-compare --merge "$BASE" "$LOCAL" "$REMOTE" --output "$MERGED"'` with `trustExitCode` makes it Git's merge tool. The window's Close button returns to Git, and the exit status says whether the file was resolved.
- `parallax-compare DIR` in a repository with conflicts, or *Resolve conflicts in a repository…* in New comparison, lists the conflicted files of a merge, rebase, cherry-pick or revert, with the branch names of both sides.
- Binary files, symbolic links and files deleted on one side are resolved as a whole: Keep local or Take remote. Links stay links and the executable bit follows the version taken. Nothing is staged until Stage resolved files.
- New comparison can also merge any three files into a result file.

## Syntax-aware merging

- Where lines conflict, the merge also merges by the syntax of the file: struct fields, imports, functions or JSON keys added by both sides at the same place.
- Built in by default: [weave](https://github.com/Ataraxy-Labs/weave) (MIT OR Apache-2.0) merges functions, classes and keys as units, in milliseconds and without installation.
- Optionally [mergiraf](https://mergiraf.org), installed separately (GPL-3.0; it is run as its own program, never bundled), which also merges changes within a line.
- Solutions are offered on each conflict ("✦ Syntax-aware", Alt+S) or for all at once, never applied by themselves. Where Git joined two conflicts and only one can be solved, "✦ Narrow down" leaves the smaller one. A banner points out conflicts the line merge missed, such as the same key added on both sides.
- The conflicts list marks files that merge completely by syntax and can solve them in one step, for review before staging. The ✦ Syntax-aware menu chooses Built in, mergiraf or Off.

## Command line

- `parallax merge BASE LOCAL REMOTE [-o OUT]` merges three versions of a file like `git merge-file`; the sources can be any supported form, such as `repo@main:src/a.c`. Options set the marker style (`--style diff3|zdiff3`) and labels (`-L`).
- `--strategy syntax` merges by syntax with the built-in engine; `--strategy mergiraf` uses mergiraf.
- `parallax merge --repo .` merges a repository's conflicted files again and writes those that merge cleanly. Exit status: 0 merged, 1 conflicts left, 2 error.

## Fixes

- YAML: keys of different types (`1` and `"1"`) are no longer merged into one, and explicit tags such as `!!float 1` keep their type. Both could report changed files as ≈ similar (#11).
- Archives: two comparisons writing the same archive no longer lose each other's edits; writing a file where an archive has a folder is refused (#11).
- Git: annotated tags work for common-ancestor comparisons and file history; repositories no longer stay open after their comparison closes (#11).
- CSV table view: cells containing the column separator, a backslash or a line break no longer look like other cells (#11).
- Similar documents are converted once instead of three times when opened (#11).
- All nine findings of the merge review (#10) are addressed in the merge view described above.

## Validation

- 380 Rust workspace tests and 12 frontend tests passed, together with strict Clippy, formatting and Svelte checks, on Linux and Windows.
- The merge engine was compared with `git merge-file`; repository conflicts, `git mergetool` exit codes, symbolic-link and executable-mode resolutions and the syntax-aware engines were checked in the desktop app with real Git repositories.
