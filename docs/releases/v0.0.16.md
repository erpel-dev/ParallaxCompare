## Archive reliability

- Temporary-storage errors identify the affected archive and system temporary directory, including when a 7z comparison fills a different drive from the archive's own drive.
- Failed solid-7z decoders release their partial cache; subsequent reads can retry after resources become available.
- Spooled 7z and tar entries are compared as streams rather than copied into full-entry buffers. Whole-entry reads use fallible allocation and report memory failures.
- Temporary-file I/O is serialized safely for concurrent reads and decoder writes on Windows. Decoder failures wake waiting readers instead of leaving them stuck.

## File and folder views

- Filtered file views retain configurable context (0, 3 or 10 lines), with fold bars to open hidden stretches.
- Changed phrases use calmer highlighting, right-only rows use the same blue as folder statuses, and current-row copy arrows have labels.
- Wrap line wraps the selected line's displayed text in the detail pane.
- Collapsed folders show status counts; a clickable status-share bar and Change column make results easier to scan.
- Progress reports files compared versus files found, and estimates remaining time after the count settles.
- Narrow windows use compact toolbar controls and a filter menu.
- Preferences (gear or Ctrl+,) provide theme, window scaling, and default context lines. Ctrl++ / Ctrl+- / Ctrl+0 adjust scaling.

## Git

- A source such as `repo/src/lib@main` keeps its subfolder scope instead of comparing the repository root.

## Validation

- The reviewed application code passed 402 Rust tests (3 existing tests ignored), 21 frontend tests, frontend type checking, and a production frontend build.
- 3,000 additional generated fold/context projection cases passed.
- CI for the application commit passed on Linux and Windows. This does not constitute a new interactive Windows 11 desktop smoke test.
- The earlier reported Windows complete exit has not been conclusively attributed to one cause; the resource-failure fixes address reproduced backend failure paths.

## Known issues

The findings in [review #20](https://github.com/erpel-dev/ParallaxCompare/issues/20) remain open in this release:

- Root-level comparison failures can be omitted from the new error banner.
- Unprefixed error messages can be reduced to their last character in grouped summaries.
- The error count and copied diagnostic list silently cap at 20,000 entries.
- Wrap line wraps the backend's displayed slice; lines longer than 10,000 UTF-16 units can remain clipped.
- Rebuilding error summaries can stall the UI on very large failure trees.
