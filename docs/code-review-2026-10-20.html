3 · What the change does well

Security posture of the PR resolver

crates/parallax-core/src/pull_request.rs

  • URL parsing rejects credentials-in-URL, non-HTTPS, path tricks (%2F, ./..), bogus numbers, and unknown sub-paths — each case has a test.
  • Server-returned data is treated as hostile: clone URL must stay on the requested host (SSRF), commit IDs must be 40 hex chars (an --upload-pack=bad payload is explicitly tested), SSH URLs validated and checked for control characters.
  • GH_PROMPT_DISABLED=1 + shared runner with stdin(null) prevents credential prompts from hanging the app.
  • TOCTOU handling: if the head moves while opening, the fetched SHA mismatch is detected and the user is asked to re-paste — tested both ways.

≈-similar rules fail closed

convert/dcm.rs, convert/odx.rs, convert/mod.rs

Unknown DCM statements, malformed files, or non-round-trip encodings return None/false — a parse failure can never become proof of equivalence. The explicit l.encode() != left round-trip check in content_equal is a nice touch: lossy UTF‑16 decoding cannot fake equality through replacement characters.

Correct-by-construction numerics and XML handling

  • DCM number() normalizes decimals exactly (9007199254740993 survives; NaN/inf/exponent overflow rejected) — right call for calibration data.
  • ODX rejects DOCTYPE (XXE), bounds node count/depth, keeps processing instructions and vendor namespaces visible, and only sorts keyed definition sets — wire-order data (PARAMS, COMPU-SCALES) is untouched.
  • Resource limits are consistent with the codebase's existing 64 MiB view budget.

Extraction of process::run

Removing the ~40 duplicated subprocess lines from remote::git and sharing them with gh is the right refactor, with tests for missing-binary, failing-command, and stall-timeout behaviour. Behavioural parity with the old git runner is preserved (GIT_TERMINAL_PROMPT, Windows creation flags, 20 ms poll loop).

4 · Findings

M1 · FIXED Drain-thread joins can outlive the deadline

crates/parallax-core/src/process.rs · run()

Correction (2026-10-20, measured): the original text put this after the kill path, but the timeout path returns before joining — a stalled command with a grandchild holding the pipes returned in 301 ms with a 300 ms limit. The real unbounded wait was on the success path: sh -c 'sleep 3 & exit 0' with a 200 ms limit returned after 3.00 s, because the child exits while the grandchild keeps the pipes open, and stdout.join() waits for EOF. The timeout path instead leaked both drain threads.

Fixed: each pipe is now drained into an Arc<Mutex<Vec<u8>>> and signalled over a channel, and Drain::until(deadline) waits with recv_timeout until the deadline before returning whatever arrived. Both pipes share one absolute deadline, so a lingering helper can delay a call by at most DRAIN_GRACE (1 s) after the command exits; the timeout path still answers immediately. The grace deliberately applies even when the command ends at its limit, since truncating a successful result’s tail would be worse than returning 1 s later. Regression tests cover a grandchild on the success path and on the timeout path; the earlier 3 s hang is now bounded by the grace.

Still open: child.kill() only reaps the direct child, so a helper that never exits keeps its drain thread alive (idle, bounded buffer). A process-group kill (process_group(0) + libc::kill(-pid)) would close that too, at the cost of a platform-specific dependency.

M2 · MEDIUM DCM rejects valid files where WERT precedes ST/Y

crates/parallax-core/src/convert/dcm.rs · Object::validate / ST/Y handling

rows.push(obj.values.len()) records the offset when ST/Y is seen, and rows[0] != 0 then forces every map to declare ST/Y before its first WERT row. Several vendor tools (and DCM 3.0-style exports — note the header version is accepted at any value) interleave or emit values first. Such files currently error, which is correct behaviour (no false ≈) but makes them unopenable in the Calibration view.

Correction (2026-10-20): the earlier claim that “a test even asserts the reverse order fails” does not hold up — the tall test that swaps ST/Y 9999\nWERT 9999 fails because it also drops the row count to 9 999 against y.len() == 10 000, not because of the ordering rule. No test pins the ordering decision either way.

Suggestion: confirm against ASAM MCD-3-3 and real exports; if both orders occur, record row starts as “offset known” vs “position implied” instead of requiring 0. A fixture with the values-first order would pin the decision either way.

M3 · FIXED Frontend PR predicate differs from the backend

app/src/lib/api.ts · isPullRequestUrl vs pull_request.rs

The original finding was the http: mismatch: isPullRequestUrl accepted it, so a pasted http://ghe.internal/o/r/pull/1 routed to openPullRequest, which always failed, and SidePicker skipped ref completion for it. Re-checking showed the drift was wider: the regex also accepted /pull/0, /pull/42abc, /pull/+42, percent-encoded owner/repo segments and credentials-in-URL, all of which PullRequestUrl::parse rejects.

Fixed: the predicate now mirrors the parser — https: only, no username/password, owner and repo limited to [A-Za-z0-9._-] (and not ./..), a positive u64 pull number, and /files|commits|checks|changes|overview as the only extra segment. An http:// PR link now goes down the ordinary source path, where the error explains the problem instead of a dead-end PR open.

L1 · LOW Pinned PR refs are never pruned from the shared cache

crates/parallax-core/src/remote.rs · pin_commit

Every opened PR adds refs/parallax/commits/<sha>, which permanently protects those objects from gc. Repeated use on large repos grows the cache without a bound. Consider a prune step (e.g. drop pin refs older than N days before fetch) or document the trade-off in the cache directory's README comment.

L2 · LOW .pdx claimed by extension alone

crates/parallax-core/src/vfs/archive.rs

Consistent with how .jar etc. are handled, but .pdx is also used by unrelated formats (Epi Info, some PLC data). Since mis-detection only costs a view, not correctness (content compare falls back), this is acceptable — a magic-bytes check on first open would settle it.

L3 · LOW DCM lexer treats backslash as an escape

convert/dcm.rs · tokenize

DCM strings quote with doubled "", so a strict reader gives a backslash no special meaning. This lexer does: \\ → \ and \" → ".

Correction (2026-10-20, measured): this is not the harmless “permissive superset” the first pass described. TEXT "C:\\cal" renders as C:\cal (lossy), and a string that legitimately ends in a backslash — TEXT "C:\dir\" — fails with unterminated string, making an otherwise valid file unopenable. Rare, and equality is unaffected because both sides parse the same way, but it should be either documented as deliberate or narrowed to the backslash-free reading the format implies.

L4 · LOW PR tab mutates the session spec for display

app/src/App.svelte · sessionTab

session.left.rev = "Merge base" overwrites the 40-hex rev the backend reports with a display label inside the session model. It works (the real spec lives in request), but any future code that reads session.*.rev for identity — not display — will get a lie. A display-only field would be safer.

L5 · LOW 20 ms poll adds latency to every git/gh call

crates/parallax-core/src/process.rs

Inherited from the old git runner, fine in practice; noted since the helper is now shared with the interactive PR path where a few extra ms are user-visible. A blocking wait on a watcher thread would remove it.
