ParallaxCompare — attack surface and hardening report

A whole-codebase security review of the Rust comparison engine, its ~60 file-format parsers, the Tauri IPC layer and the Svelte front end: where the trust boundaries are, how an attacker would reach them, and what to fix first.

Repository erpel-dev/ParallaxCompare Revision 9f7d5cd (v0.0.9) Date 2026-10-20 Scope crates/parallax-core, crates/parallax-cli, app/src-tauri, app/src, CI Findings 0 critical · 2 high · 5 medium · 7 low

Remediated Findings 1–7 (the two High and the five Medium ones) were fixed on 2026-10-20; findings 8–13 are still open.

1. Executive summary

ParallaxCompare is a desktop diff tool that opens files it did not create. That single sentence defines its threat model: everything it displays is untrusted input — archive members, document bodies, media headers, Git trees fetched from the network, and the GitHub API answers that name them.

The good news is that the codebase is visibly written with that in mind. The hand-written binary parsers validate every length and offset against the buffer they came from, the four riskiest parsers are wrapped in catch_unwind, Jinja chat templates execute under a fuel limit, archive member names pass through a normalize() that rejects .., Git and gh are invoked with --end-of-options and validated arguments, the webview CSP is strict and the front end has no HTML injection sink. No memory-corruption, command-injection, XXE or XSS vulnerability was found in the Rust or TypeScript code itself.

What remains are boundary and robustness problems, concentrated in four places:

  1. LibreOffice conversion uses a predictable, symlink-following temp directory in the shared temp folder — a local attacker can plant a symlink and redirect writes made with the victim's privileges (office.rs:411).
  2. Relative paths from the webview are not confined to the comparison roots. .. is never rejected on the write/delete path and the empty path resolves to the root itself, so the IPC layer is one renderer compromise — or one UI bug — away from arbitrary file write and permanent deletion outside the folders the user opened.
  3. Crafted archives can kill the app (and on some systems the session): allocation sizes are taken from archive headers, tar payloads are fully decompressed into RAM at open time, and directory creation recurses per path component.
  4. LibreOffice is the parser for untrusted legacy documents — one of the largest native attack surfaces on a typical desktop — and it is invoked without any sandbox.

2. Trust boundaries

The application has exactly one privilege boundary that matters: the Rust process runs with the full rights of the logged-in user, and everything the webview asks it to do is done with those rights. Tauri's capability system guards plugin commands; the 37 custom commands in commands.rs are not covered by capabilities/default.json at all. That is normal for Tauri, but it makes the renderer a fully privileged peer: any script that runs there can read, copy and delete any file the user can.

Untrusted input
Files, archives, repos and PR links the user opens. Attacker fully controls bytes, names and headers.
parallax-core parsers
~60 hand-written format readers. Bounds-checked; the risky four are panic-wrapped. Solid.
VFS layer
Local files, archives, Git trees. normalize() rejects .. for archive and Git members, but not for paths arriving from the UI.
Tauri IPC — full user privileges
File read, copy, write, permanent delete, "open with default app". No path confinement, no capability restriction.
Svelte renderer
Strict CSP, no innerHTML, SVG only inside <img>. Solid.

How to read the severities below. A finding is rated High when an attacker with a plausible position (a local user on a shared machine, a document or link sent to the victim) obtains a concrete, damaging primitive without needing a second, unrelated bug. Findings that need a renderer compromise first are rated Medium — they are the reason a renderer compromise would be catastrophic rather than cosmetic, which is exactly why they should be closed.

4. Findings in detail

High 1 · Predictable, symlink-following temp directory for document conversion

crates/parallax-core/src/convert/office.rs:411–459 (also unique() at 447)

Attacker controls
A local account on the same machine, plus the document the victim compares (easy to arrange: "can you diff these two builds / these two contracts for me?").
Root cause
The conversion directory is temp_dir()/parallax-convert-<pid>-<counter>. The PID is readable from /proc or ps, and the counter starts at 0 for every process, so the name is fully predictable. It is then created with create_dir_all, which succeeds when the path already exists — including as a symlink — and the document is written with std::fs::write, which follows symlinks. The directory is also handed to LibreOffice as --outdir, and the result is read back with std::fs::read, again following links.
Impact
Two directions. Integrity: a symlink planted at /tmp/parallax-convert-<pid>-0/input.doc makes the app write the attacker's bytes to any path the victim can write, with the victim's privileges (startup entries, shell profiles, SSH authorized_keys). Confidentiality: the directory is world-readable under the default umask, so confidential documents being compared are left readable to other local users while the conversion runs.
Remediation
Use an exclusive, randomly named, owner-only directory and stop following links:
let dir = tempfile::Builder::new()
    .prefix("parallax-convert-")
    .tempdir()?;                          // mkdtemp semantics, mode 0700
let input = dir.path().join(format!("input.{ext}"));
let mut f = std::fs::OpenOptions::new().write(true).create_new(true).open(&input)?;
f.write_all(data)?;                       // refuses a pre-planted symlink
// keep the TempDir guard; it removes the directory on drop

High 2 · Relative paths from the webview are not confined to the compared roots

app/src-tauri/src/commands.rs:529, 578, 597, 785, 1431 · crates/parallax-core/src/vfs/local.rs:45–49 · source.rs:102–104

Attacker controls
Whatever script runs in the webview. Today that is nothing, because the CSP is strict and there is no HTML sink — but it is also what a future {@html}, a dependency with a DOM sink, a WebKit bug or a developer with DevTools open reduces to. Separately, a bug or injection in the UI itself makes the same primitive reachable.
Root cause
Source::path() is a plain string join and LocalFs::abs() forwards every component verbatim, so .. resolves outside the root. A normalize() helper that rejects .. already exists and is applied to archive and Git members and to SourceSpec::child, but never on the operation paths. The Tauri commands are not covered by capabilities/default.json, and delete_entries takes permanent: bool straight from the caller, with the confirmation living only in the UI.
Impact
delete_entries({ paths: [""], permanent: true }) calls remove_dir_all on the comparison root — the whole folder, unrecoverably. paths: ["../../.ssh"] deletes files anywhere the user can. copy_file_as and copy_entries write attacker-chosen content to arbitrary paths; expand and open_file_diff read arbitrary files back out.
Remediation
Make confinement a property of the VFS layer rather than of each call site:
// crates/parallax-core/src/vfs/local.rs
fn abs(&self, path: &str) -> PathBuf {
    let mut p = self.root.clone();
    for part in path.split('/').filter(|p| !p.is_empty()) {
        if part == "." { continue; }
        // ".." is never a legitimate member: it cannot come from a listing,
        // a Git tree or an archive index, only from a caller.
        debug_assert!(part != "..", "unconfined path: {path}");
        p.push(part);
    }
    p
}

Return an error instead of pushing .., and reject "" in the mutating commands (delete_entries, copy_entries, copy_file_as) where it means "the root". Then add a regression test in crates/parallax-core/tests that asserts a traversal attempt fails for every Vfs implementation.

Medium 3 · Archive header sizes drive allocations

crates/parallax-core/src/vfs/archive.rs:276 (tar), 330 (7z), 394 (zip) · vfs/archive/write.rs:186

Attacker controls
The bytes of any archive the user opens.
Impact
A zip central-directory entry that declares 4 GiB uncompressed, or a tar header claiming terabytes, makes Vec::with_capacity(n) request that much up front. Allocation failure in Rust is not a catchable error: it aborts the process. The archive need not contain any data, so a few hundred bytes kill the application instantly, and on a machine without swap the OOM killer may take more than the app. This applies to merely opening a tar/7z (indexing reads the stream) and to clicking a file inside a zip.
Remediation
Never trust a claimed size for allocation; clamp and let the reader grow the buffer. Also enforce a global decompression budget (for example 2 GiB per archive or 100× the compressed size) and surface a clear error instead of a crash.
let hint = (file.size() as usize).min(1 << 20);
let mut buf = Vec::with_capacity(hint);
file.read_to_end(&mut buf)?;   // grows as needed, bounded by our budget check

Medium 4 · Stack overflow while indexing deep archive paths

crates/parallax-core/src/vfs/archive.rs:72–87

Root cause
Index::ensure_dir recurses once per parent directory. Archive member names have no length limit worth relying on (tar long-name entries reach megabytes), so a name made of tens of thousands of a/ components overflows the worker stack while the archive is indexed — before anything is displayed.
Impact
Process abort on opening a crafted archive (Rust's stack-overflow guard aborts, it does not unwind).
Remediation
Walk the components iteratively, and cap the nesting depth (a few hundred is generous for real archives); skip deeper entries with a diagnostic.

Medium 5 · tar streams are decompressed entirely into memory at open

crates/parallax-core/src/vfs/archive.rs:256–291

Root cause
open_tar drives the decoder to the end of the stream and keeps every regular file's bytes in a HashMap<String, Arc<Vec<u8>>> so that listing never decompresses twice. Decompression ratios of 1000:1 are trivial for gzip, xz and bzip2, and for .tar.gz the ratio is not bounded by anything the app checks.
Impact
A 1 MB archive expands to gigabytes of resident memory the moment it is opened — a crash, or a machine-wide memory squeeze. The zip and 7z backends avoid this by decoding lazily; tar is the outlier.
Remediation
Index tar entries from the headers only (name, size, mtime, type) and remember the byte range; decompress a member on demand into a seekable cache, as the other backends do. If a full decode stays, cap the total uncompressed size while streaming and abort with a message.

Medium 6 · LibreOffice parses untrusted legacy documents without a sandbox

crates/parallax-core/src/convert/office.rs:374–443

Context
Native readers exist for .doc, .xls and .ppt, but when one fails or the format is .vsd, the bytes are handed to soffice --headless --convert-to. The Rust parsers in this repository are memory-safe by construction; LibreOffice's import filters are C++ and have a long history of memory-corruption bugs reachable from a document alone.
Impact
A malicious document opens a native parser with the user's full rights, bypassing the entire "bounds-checked Rust" argument. The 90-second timeout and the private profile limit resources but do not contain code execution.
Remediation
Give the converter a small blast radius: run it under bwrap/firejail (or a Windows AppContainer / Job Object) with only the temp directory visible, no network, a read-only home, and a dedicated low-privilege profile. Failing that, make the fallback opt-in and label it in the UI as "external converter".

Medium 7 · Plaintext and unauthenticated remotes are accepted

crates/parallax-core/src/remote.rs:24–27, 236–262

Root cause
is_remote() accepts http:// and git:// in addition to https:// and ssh://, and fetch() passes them to git fetch. There is host validation in the pull-request path, but a repository URL typed or pasted by the user gets none of it.
Impact
A network attacker (public Wi-Fi, a hostile proxy) can substitute the contents being compared. For a tool whose purpose is to prove that two artifacts are identical, silently comparing attacker-chosen content is a meaningful integrity failure. file:// additionally lets a pasted "URL" read local repositories — harmless in itself, but it makes a link's effective scope surprising.
Remediation
Accept only https:// and ssh:// by default; put http://, git:// and file:// behind an explicit "allow insecure remote" setting and show a warning in the path bar. git can also be told -c protocol.ext.allow=never and GIT_ALLOW_PROTOCOL=https:ssh for defence in depth.

Low 8 · CSP directives that do not inherit from default-src

app/src-tauri/tauri.conf.json:24

Observation
The policy is already good — default-src 'self', no unsafe-inline scripts, no withGlobalTauri, no remote origins. But base-uri, form-action, frame-ancestors and object-src are not covered by default-src, so they fall back to "allow". A <base> injection would redirect module loading; a plugin document could be embedded.
Remediation
Extend to: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; object-src 'none'; base-uri 'self'; form-action 'none'; frame-ancestors 'none'; connect-src ipc: http://ipc.localhost.

Low 9 · Subprocesses resolved through PATH

remote.rs:276 · pull_request.rs:120 · convert/office.rs:352–368

Observation
Command::new("git"), Command::new("gh") and the PATH search for soffice execute whatever the environment points at. Two realistic amplifiers: on Windows the process search order historically includes the working directory, and the app is designed to be launched from a repository (as git difftool) — so a git.exe in that directory is a candidate; and a per-user PATH entry in a writable location is a standard persistence foothold.
Remediation
Resolve each tool once at startup to an absolute path, refuse paths inside the compared tree or inside the temp directory, and pass CREATE_NO_WINDOW plus an explicit environment. For soffice, prefer the well-known install locations over PATH.

Low 10 · Terminal escape injection in the CLI

crates/parallax-cli/src/main.rs (diff rendering and Paint)

Observation
Line content is written to stdout unchanged. A compared file containing ANSI/OSC sequences can rewrite the scrollback, hide or forge output, or set the clipboard via OSC 52 on terminals that allow it. This is the usual reason git escapes control characters.
Remediation
When stdout is a terminal, render control characters as visible escapes (at least C0 and DEL, plus ESC in file names and diff text); add --color=never-style raw output only on explicit request.

Low 11 · CI supply chain

.github/workflows/ci.yml · release.yml

Observation
Actions are pinned to mutable tags (actions/checkout@v4, Swatinem/rust-cache@v2, dtolnay/rust-toolchain@stable). A compromised or retagged action runs with the workflow token. ci.yml sets no explicit permissions:, so it inherits the repository default rather than least privilege. In release.yml the workflow_dispatch input is interpolated directly into bash ("dist/ParallaxCompare-${TAG}-linux-x86_64.AppImage") — only reachable by people with write access, but it is still shell injection (CWE-78) and should not depend on that. The release job does pin the downloaded linuxdeploy AppImage by SHA-256, which is good practice and shows the pattern is understood.
Remediation
Pin every action to a full commit SHA (Dependabot can maintain them), add permissions: contents: read to the CI workflow, pass workflow inputs through env: and quote "$TAG", and add cargo audit plus npm audit --omit=dev as a non-blocking job.

Low 12 · Image decoding without explicit limits

crates/parallax-core/src/convert/image_diff.rs:135, 227; image_meta/mod.rs:86

Observation
image::load_from_memory_with_format uses the crate defaults: no width/height cap and a 512 MiB allocation ceiling. A few-kilobyte PNG that decodes to a huge canvas therefore still costs hundreds of megabytes before the 120 M-pixel mask check applies, and to_rgba8() multiplies it by four.
Remediation
Set an explicit image::Limits (for example 20 000 × 20 000 and 256 MiB) on an ImageReader before decoding, and reject larger images with a message that points at the hex view.

Low 13 · Symlinks recreated from archive content

crates/parallax-core/src/ops.rs:167–175 · vfs/local.rs:257–262

Observation
Copying a symlink out of an archive creates it with the target stored in the archive, which may be /etc/passwd or ../../.ssh/authorized_keys. The subsequent write path is already careful — replace_file writes to a temporary name and renames over the link, so a link cannot be used to write through it — and list/stat never follow links. The residual risk is a link placed by the tool that a different program later follows.
Remediation
Warn before creating links with absolute or escaping targets, or store them as link entries that are only materialised on explicit extract.

5. How this application could be attacked

Scenario A — "Please compare these two builds for me"

The most realistic attack needs no local account and no network position, only that the victim opens files the attacker supplied — exactly what a diff tool is for.

  1. The attacker sends two archives. One contains an entry whose header declares a multi-gigabyte size (finding 3) or a tar stream that expands without bound (finding 5).
  2. The victim drops them into the app. Indexing or the first click on a member aborts the process or exhausts memory. Repeated indefinitely, it is a reliable crash of the tool the team relies on for release verification.
  3. Alternatively the archive carries a .doc and the victim opens the document view, handing the file to LibreOffice (finding 6). Any bug in the importer runs as the victim.

Scenario B — a link is pasted

The path bar accepts https://github.com/owner/repo/blob/main/x and pull-request URLs, then runs git ls-remote, git fetch and gh api against them. Validation here is genuinely careful (host pinning for PRs, 40-hex commit checks, --end-of-options on every Git argument), so the interesting paths are: a plain http:// or git:// URL, where the fetched content can be swapped in transit (finding 7); and a URL for an arbitrary host, which makes the victim's machine issue requests to it and reflects the error text back into the UI.

Scenario C — a local attacker on a shared machine

Wait for the victim to convert a legacy document, then win the race on /tmp/parallax-convert-<pid>-<n> (finding 1). The name is predictable, so the symlink can be planted before the conversion starts; no race is even required. What follows is an arbitrary write with the victim's rights, or a read of the document being compared.

Scenario D — anything executes in the renderer

Today nothing does: there is no innerHTML, no {@html}, no eval, SVG is only ever loaded inside <img> where scripting is disabled, and the CSP blocks inline script and remote origins. That is a strong position — but it is a single control. If a future feature renders Markdown, an inline SVG, or a template from a dependency, the injected script inherits the whole IPC surface: delete_entries with permanent: true, copy_file_as, open_source and friends, none of which checks that the path it is given lies inside the folder the user opened (finding 2). Closing finding 2 converts "one XSS is game over" into "one XSS is annoying".

Scenario E — supply chain

~40 third-party crates parse attacker-controlled data (pdf-extract, mail-parser, calamine, cfb, syntect/oniguruma, image, sevenz-rust2, zip). None of them is audited by this review, and CI runs neither cargo audit nor a fuzzer over the view layer, although tests/fuzz_views.rs shows the shape such a harness would take.

6. What is already solid

  • Parser hygiene. Lengths, offsets and counts are checked with .get(), checked_add and explicit bounds before use — for example sqlite.rs:158 refuses a payload larger than the file, parquet.rs:169 caps a length at the remaining input and parquet.rs:174 caps recursion at 32, dotnet.rs:378 verifies that the decoded tables fit the metadata stream. This is not accidental; it is a consistent style.
  • Panic containment. The converters that wrap C-style or panic-prone dependencies (pdf-extract, mail-parser, calamine, the native .doc reader) are wrapped in catch_unwind and degrade to the hex/text view.
  • Template execution is bounded. Jinja chat templates taken from model files run with set_fuel and no filesystem or network access.
  • Archive and Git member names are normalised. normalize() rejects .. outright and there is a regression test for it; tar hard links without a target are represented as links rather than dereferenced.
  • Writes are atomic and symlink-safe. replace_file writes to an exclusively created temporary name and renames over the target, so a symlink at the destination is replaced rather than followed. Deleting defaults to the trash.
  • Subprocess handling is careful. No shell is used, arguments are validated, --end-of-options separates them from revisions, stdin is closed, terminal prompts are disabled, and every call has a deadline and non-interactive output.
  • The pull-request resolver validates server answers: HTTPS only, no credentials in URLs, owner/repo restricted to a safe alphabet, commit IDs required to be 40 hex characters, and the returned clone URL pinned to the requested host.
  • No secrets, no evaluated config, no unsafe code in the parsers. The only unsafe in the engine is the read-only mmap in vfs/local.rs:236.

The one structural change worth more than all the individual fixes: put the containment check inside Vfs, so that no command, present or future, can name a path outside its root. Every other fix here protects one call path; that one protects the boundary itself.

8. Method and limitations

This was a manual, whole-codebase review of revision 9f7d5cd: the Tauri configuration, capabilities and all 37 IPC commands; the VFS layer (local, archive, Git, mount); the comparison and file-operation engines; the process-execution helpers; the network paths (remote.rs, pull_request.rs); the front end's rendering and IPC usage; and the CI workflows. Where a parser was checked, it was checked representatively — the allocation, bounds-checking, recursion and decompression patterns that recur across the ~60 converters — rather than line by line in every one of the ~25 000 lines.

Not covered: dynamic testing, fuzzing or exploitation. No proof-of-concept archives were built; the severity of findings 3–5 rests on reading the allocation and recursion sites, which is reliable for Vec::with_capacity and recursion depth but says nothing about how the zip, tar, sevenz-rust2 or image crates themselves behave on malformed input. Third-party crates were not audited, no cargo audit or npm audit was run, and no binary-level or WebKit-level analysis was performed. Findings 13 and the Git-tree case in finding 2's neighbourhood are reported as hardening gaps, not confirmed exploits.
