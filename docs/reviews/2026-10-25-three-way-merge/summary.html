P1 M01 · Saving silently overwrites external changes to the merge output

  1. Create a clean three-file merge with an existing result file.
  2. After the merge opens, change the result file from another process.
  3. Click Save result.

Observed: ONE two three four FIVE

Expected: Reject the stale save and offer reload, Save As or explicit overwrite.

Fix direction: Capture the output bytes/existence when opening and after each save; check again before the atomic replacement. Protect duplicate open merges targeting the same file too.

P1 M02 · Taking a side of a symlink conflict replaces the symlink with a regular file

  1. Create a repository with both branches changing a symlink target.
  2. Open Resolve conflicts and click Take remote for link.
  3. Stage resolved files and inspect git ls-files -s link.

Observed: link is a regular file containing 'remote-target'; the UI marks it resolved.

Expected: Keep a symlink pointing at remote-target and stage mode 120000.

Fix direction: Use each stage mode when resolving whole files; create symlinks for 120000, preserve 100755/100644 and handle gitlinks separately. Symlink conflicts must not open as editable text.

P2 M03 · Taking a whole version ignores the chosen executable bit

  1. In a rebase conflict, base and remote script.sh are executable (stage mode 100755), while local is non-executable (100644).
  2. Click Take remote in the repository conflict list.
  3. Stage the resolved file and inspect git ls-files -s script.sh.

Observed: The remote content is taken, but the file remains non-executable (0o600).

Expected: Restore the chosen stage executable bit and stage mode 100755.

Fix direction: Use stage.mode when resolving whole files; pass permissions to replacement. Compare executable bits independently of the process umask.

P2 M05 · Merge input lines are clipped with no horizontal scrolling

  1. Open three files with a shared 190-character prefix and different text after it.
  2. Try to inspect the changed suffix in Local/Base/Remote.

Observed: At a 1400 px window, each code cell has 420–421 px visible width versus 1343–1364 px of text. Code and cells use overflow:hidden; the input pane scrollWidth equals clientWidth (1400 px), so scrolling cannot reveal the suffix.

Expected: Allow horizontal scrolling or wrapping so the changed text can be inspected before choosing a side.

Fix direction: Add per-pane horizontal scroll with synchronized headers, or configurable wrapping. The result pane needs the same treatment; retain a way to inspect backend-truncated line tails.

P2 M07 · Merge initialization scales quadratically with many independent conflicts

  1. Generate N conflict lines separated by six unchanged context lines.
  2. Open the three files in a merge.
  3. Repeat for 500, 1000, 2000 and 4000 conflicts using the optimized build.

Observed: For 3500 / 7000 / 14000 / 28000 input lines (about 49 / 98 / 204 / 416 KB per input), open_merge takes 0.126 / 0.422 / 1.944 / 7.069 seconds. Doubling the input and conflicts roughly quadruples initialization time.

Expected: Avoid repeated whole-file scans when constructing blocks; loading small sub-megabyte inputs should not take seconds.

Fix direction: MergeSession::new calls content once per block, and content splits all three entire documents into line vectors every time. Reuse line offsets/slices for each block. Profile info()/stats serialization separately after removing that scan.

Source: crates/parallax-core/src/merge_session.rs:174 · crates/parallax-core/src/merge_session.rs:235

P2 M08 · The default syntax pass adds substantial memory for an entirely unchanged plain-text merge

  1. In a fresh process, merge three identical 14,000,000-byte text files containing one million lines.
  2. Measure main-process RSS after open_merge.
  3. Run merge_structured with the built-in engine, which the GUI runs by default.

Observed: Main-process RSS rises from 182,148 KiB baseline to 330,888 KiB after opening, then 566,716 KiB after the redundant syntax pass—about 230 MiB extra although there are no changes or conflicts. Closing leaves allocator-retained memory; a leak was not established.

Expected: Skip syntax work when all three texts are identical, and avoid cloning whole documents for a no-op.

Fix direction: Add a trivial unchanged-merge fast path before copying texts or invoking the engine. Retain syntax checks for nontrivial clean line merges, since they may reveal semantic conflicts. Profile temporary vectors and owned strings in set_syntax_result.

P2 M09 · Side shortcuts after Narrow down discard the syntax-merged parts of the conflict

  1. Merge a Rust struct where local adds a local field, remote adds a remote field, and both sides edit the following function differently.
  2. Choose ✦ Narrow down. The result retains both fields and leaves only the function call conflicted.
  3. Focus the merge and press Alt+Left to take the local side.

Observed: The remote field disappears as the shortcut replaces the entire original line-conflict block. The counter changes to All 1 conflict resolved. The visible buttons had deliberately offered only manual editing and Undo choice after narrowing.

Expected: Resolve only the remaining inner conflict, retaining the fields already merged, or disable whole-block side shortcuts after narrowing and explain their scope.

Fix direction: Guard Alt+arrow handling for partially narrowed syntax choices, or model the remaining marker ranges as new conflicts. The same scope policy should cover local, remote, base and both-side shortcuts.

What worked

  • All five conflict choices, undo/redo, keyboard resolution and clean saves.
  • CRLF, missing final newline, Unicode and UTF-16/legacy encoding round-trips. Unrepresentable edits fail safely and preserve the output file.
  • Text, binary, delete/modify and add/add repository conflicts; merge, rebase and cherry-pick labels; explicit staging of selected resolutions.
  • Built-in JSON/Rust solutions and batch application; actual mergiraf 0.20.0 combines separate argument edits on one line. Missing-engine diagnostics are actionable.
  • Git mergetool: resolved save returns 0 and Git stages the file; cancel returns 1; saving markers returns 1 and keeps the file unmerged.
  • Million-line virtual scrolling, reaching line 1,000,000 and saving an edit to that exact line.
  • Backend merging of Git revisions and archive members without checkout or extraction.

Validation and limits

368 Rust tests passed, with 3 existing ignored; 12 frontend tests passed. Svelte check reports zero errors and warnings. Optimized native build succeeded.

A seeded 600-case CLI comparison against git merge-file agreed on clean versus conflicted outcomes in all cases. Fourteen cases differed in conflict placement/text; repeated-line alignment choices can differ, so these were not counted as independent defects or as byte-for-byte Git compatibility.

Some exploratory harness attempts needed timing or quoting corrections. They are retained in logs, were rerun as needed, and are not counted as product findings. The report separates confirmed defects from unsupported platforms and allocator behavior. Windows, macOS and network shares were not exercised. No memory leak was established.
